# Harmony Spaces AI

> AI-powered room visualization · 8 design styles 

An interior design platform that lets users visualise their room in 8 different aesthetic styles — from modern minimalist to rustic warm — through an AI-assisted image generation workflow. Designed across 3 core screens with a focus on visual polish and intuitive UX.

---

## What It Does

Interior design decisions are hard to visualise mentally. Harmony Spaces AI solves this by letting users upload their room, select preferences (style, colour palette, mood), and generate a redesigned version — no design background required.

---

## Features

- **8 design styles** — modern, minimal, rustic, bohemian, industrial, Scandinavian, classic, and contemporary
- **Multi-parameter customisation** — room type, colour palette, and mood inputs
- **AI image generation** — personalised design output based on selections
- **3-screen flow** — upload → preferences → results
- **Responsive design** — works across mobile and desktop viewports

---

## Tech Stack

| Layer | Technology |
|---|---|
| Frontend | React, TypeScript, Tailwind CSS |
| AI Workflow | AI image generation (Lovable-integrated) |
| Build Platform | Lovable (AI-assisted development) |

> **Note on the build approach:** This project was built using Lovable, an AI-assisted development platform. All product decisions — feature scope, design style selection, user flow structure, and visual direction — were made and iterated by me. This approach allowed end-to-end product shipping while I continue building manual coding skills in React and TypeScript.

## User Flow

```
1. Upload room image
        ↓
2. Select: room type · colour palette · mood · design style
        ↓
3. AI generates redesigned room visualization
        ↓
4. View results · try different styles
```

---

## What I Learned

- Defining clear input parameters (not just "style" but also mood and palette) leads to significantly more useful AI outputs
- Product design is about deciding what NOT to include — keeping the flow to 3 screens was a deliberate choice to reduce decision fatigue
- AI-assisted development tools shift the bottleneck from "can I build this?" to "should I build this?" — which is a better problem to have
